# 飞书驱动的 Design Digest 发布流程

## 目标

让飞书多维表格成为周刊唯一的内容后台；网站保持一个固定公开网址。索哥和同事只需在飞书维护选题，发布时由 Codex 完成中英编辑、网站更新与上线核对。

## 范围

本期实现三件事：

1. 将静态网站迁移到 GitHub 驱动的 Netlify 项目，使每次更新覆盖同一公开网址。
2. 为现有飞书表增加发布所需字段和视图。
3. 建立“飞书选题 → 编辑整理 → 网站预览 → 固定网址上线 → 飞书回填”的工作流。

不在本期实现独立的网站 CMS，也不在网站上直接存储或编辑选题；飞书就是内容后台，避免双份内容和双重登录。

## 信息结构

现有字段继续保留：资源推荐、描述、网址、图片、标签、上传人。

新增字段：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| 期号 | 数字 | 将每条资源归入某一期周刊，例如 1、2、3。 |
| 发布状态 | 单选 | 候选、待发布、已发布。 |
| 网站标题（中文） | 文本 | 发布时写入的中文编辑标题。 |
| 网站标题（英文） | 文本 | 发布时写入的英文标题。 |
| 网站导读（英文） | 文本 | 发布时写入的英文摘要。 |
| 上线网址 | URL | 本期发布后的固定站点地址。 |

增加“待发布”视图：过滤发布状态为“待发布”，按期号和录入顺序展示。每期恰好选 10 条后才进入发布。

## 发布流程

1. 团队在飞书录入资源、原始描述、链接、封面和标签。
2. 索哥将拟上线的十条标记为“待发布”，并告诉 Codex 发布第 N 期。
3. Codex 读取对应期号的十条内容，完成中文标题的编辑判断、英文标题与英文导读，并使用飞书的原图。
4. Codex 更新网站内容文件，在本地核对十条数量、图片、链接及语言切换。
5. 更新提交到 GitHub；Netlify 自动构建并覆盖同一个生产网址。
6. Codex 核对生产页面，回填飞书：发布状态改为“已发布”，上线网址写入固定地址。

## 技术边界

GitHub 保存网站代码、图片和各期内容；Netlify 连接该仓库并在每次提交后自动发布。飞书访问仅使用索哥已有的授权身份，凭据不写进网站代码或公开仓库。

网站保持静态生成：页面不需要登录即可阅读，加载快且成本低。内容更新由发布流程生成，因此不会依赖浏览者访问时的飞书接口。

## 失败处理

- 待发布条目不足或超过十条：停止发布并提示索哥调整飞书状态。
- 缺少网址、标题、描述或图片：在飞书中标出具体条目，暂不发布。
- GitHub 或 Netlify 发布失败：保留当前线上版本，不影响读者；修复后重新发布。
- 英文标题或导读需要调整：在飞书对应字段修改后可再次发布，网址保持不变。

## 验收标准

- 线上网址在第二次及以后的发布后保持不变。
- 飞书“待发布”视图可清楚看到下一期的十条内容。
- 每条网站内容有真实封面图、可直接跳转的原始链接、中文和英文版本。
- 发布完成后，飞书十条记录都显示“已发布”并附有上线网址。
